# ADR 0019 — Page marks: tagged form XObjects in their own content streams

* Status: accepted
* Date: 2026-09-26

## Context
SPEC §3 "Page marks": watermark (text or picture), header/footer with page/date (Gregorian + Hijri)/file
tokens, page numbers including «صفحة ١ من ٩», Bates; stored as removable tagged form XObjects; artifacts
excluded from editing text but included in search and redaction. Constraints: incremental saves (original
bytes a prefix), Arabic shaped with per-word `/ActualText` (never `/Direction /R2L`, never fill+stroke),
hostile input, the bundled fonts compiled in once, and marks that stay upright where the page is seen
(`/Rotate`, CropBox).

## Decision

### Engine: crate `warraq-marks`, `marks.*` in warraq-core
* **Model** (`model.rs`): kind (`watermark`, `header`, `footer`, `pageNumber`, `bates`), pages (0-based,
  absent = all), text template or header/footer slots `start/center/end`, picture flag, font
  (Amiri/Cairo/Inter), size, colour, opacity, rotation or `diagonal`, 9-grid position + offsets + margin,
  layer (behind/in front), picture scale (fraction of the page width), `rtl`, digit style, language,
  Bates (prefix, suffix, start, digits), file name, the caller's local date/time (`now`: the engine has no
  clock — `SystemTime` panics on wasm32) and an opaque `ui` value. Validation bounds every number and
  string. The whole model is stored in the PDF so a mark can be listed and edited later.
* **Tokens** (`tokens.rs`): `{page}`, `{pages}`, `{date}`, `{hijri}`, `{time}`, `{file}`, `{bates}`.
  Only token values take the digit style (Latin or Arabic-Indic); the literal text is kept as typed.
  Arabic: `٢٦/٩/٢٠٢٦`, `١٤٤٨/٤/١٥ هـ`; English: `2026-09-26`, `1448/4/15 AH`.
* **Hijri** (`hijri.rs`, `hijri_table.rs`): our own Umm al-Qura conversion by table — 145 twelve-bit
  month-length masks for 1356–1500 AH (1937–2077) plus the Julian day of 1 Muharram 1356, generated by
  `gen/umalqura.mjs` from ICU's calendar data through Node's `Intl` (Unicode License v3; data, not code).
  Tests use announced dates (1 Ramadan 1447 = 18 Feb 2026, Eid al-Fitr 1446 = 30 Mar 2025, 1 Muharram
  1447/1448, Arafah 1445, 1 Muharram 1420) and walk every day of the table. Outside the table the token is
  empty rather than guessed with an arithmetic calendar.
* **Drawing** (`draw.rs`): texts are laid out with warraq-edit's layout (harfrust shaping, UAX #9 visual
  runs, one `/Span <</ActualText …>> BDC` per word, fill only, no `/Direction`). The chosen bundled font
  is used when it covers the text, else the family's fallback chain (so Arabic in "Inter" falls back to
  Cairo). Every distinct text is laid out once; each face is subset to the glyphs of the whole mark and
  embedded once (`warraq_edit::fonts::embed_face`, extracted from the Edit tool's `write_face`). Opacity
  is an ExtGState (`/ca` and `/CA`); pictures are JPEG (passed through) or PNG (alpha → `/SMask`) via
  `warraq_edit::images::embed_picture`. Each page gets a **form XObject** whose `/Matrix` maps the
  *displayed* page (origin at the bottom-left of the visible box after `/Rotate`, y up) to user space and
  whose `/BBox` is the visible box, so positions, "diagonal" and "top" mean what the reader sees. Forms
  with identical drawing are shared between pages (a watermark without page tokens is one object).
* **Storage** (`store.rs`): one info dictionary per mark `<< /Type /ZOODMark /V 1 /Id (…) /Spec (json)
  [/Picture ref] >>`; the private key `/ZOODMark` (→ that dictionary) is set on the form and on a small
  **mark stream of its own** appended to the page's `/Contents` array:
  `q /Artifact <</Type /Pagination /Subtype /Watermark|/Header|/Footer /ZOODMark <id>>> BDC /ZMk1 Do EMC Q`.
  Behind-content marks go before the original streams; in-front marks after them, with the original
  content enclosed by two shared one-operator streams `q` / `Q` (`/ZOODWrap /Open|/Close`) so state the
  original leaves (CTM, clip, colours, text state) cannot move or recolour the mark. **Removal takes these
  streams off `/Contents`** (and the form's resource name off the page): no content stream is rewritten,
  so every other content byte stays identical, and when the last mark goes the wrappers go too and
  `/Contents` is exactly the original again. Update = remove + add under the same id in one incremental
  update (a picture is kept unless a new one is given). Page numbers and Bates are `/Footer`, `/Header`
  or `/Watermark` artifacts by vertical position.
* **Other applications' marks** (`foreign.rs`): pagination artifacts in the page content (`/Artifact` with
  `/Subtype /Watermark|/Header|/Footer`, or `/Type /Pagination`; inline or `/Properties` dictionaries)
  and form XObjects tagged the Acrobat way (`/PieceInfo /ADBE_CompoundType /Private /Watermark|…`) are
  listed per kind. A region is **removable** only when every operator directly inside it (outside nested
  `q … Q`) leaves the graphics state alone, or the region is enclosed by its own `q … Q` (removed with
  it), and it lies within one content stream. Removal uses warraq-edit's byte-faithful splice rewriter:
  only the affected streams are replaced by new objects. Unsafe regions are reported (`not_removable`),
  never half-removed. Artifacts nested inside other forms are not scanned.
* **RPC**: `marks.list` → `{ marks: [{ id, spec, pages }], foreign: [{ id: "foreign:<kind>", kind, pages,
  regions, removable, acrobat }] }`; `marks.add { mark, only? }` (+ picture blob; `only` draws on some
  pages while tokens still count the whole selection — used by the live preview); `marks.update { id,
  mark }`; `marks.remove { id }`. Mutating calls need the modify permission, commit one incremental update
  (encrypted files stay encrypted with the same key) and reload the last committed bytes on failure.

### Text semantics
* warraq-text marks glyphs drawn inside `/Artifact` (the flag propagates into forms), so marks are part
  of `text.extract` / `text.search` / `text.plain` by default (`artifacts: false` leaves them out) and read
  back in logical order («صفحة ٢ من ٣»). warraq-redact's find includes artifacts and its apply rewrites
  the forms a page draws, so find + apply removes mark text. warraq-edit's blocks exclude artifacts and
  never touch operators inside forms, so marks are never editable text. Each is proven by a test.

### Interface
* `app/MarksPanel.tsx` in the shared side slot (`tools/panels.ts`): tabs Watermark / Header & footer /
  Page numbers / Bates; token chips; font, size, colour; opacity; diagonal or rotation; 3×3 position grid
  (start/end follow the document direction, detected from the first page's text and switchable);
  behind/in front; page range All / Odd / Even / Custom (Arabic-Indic digits via `services/ranges.ts`).
* **Live preview**: the engine draws the mark on the viewed page of a private copy (`marks.add` with
  `only`), PDFium renders it through the viewer's `openOther` — what is shown is what will be written.
* Apply / remove / edit are core edits (`AppContext.coreEdit`): one incremental update, synchronous
  `switching`, the viewer reloads on the same page, and Undo/Redo in the panel use the shared history.

## Consequences
* A mark adds ~3 small objects per page plus one font subset per face; removing it leaves those objects
  in earlier revisions (incremental saves), but the page no longer draws them.
* Readers that ignore `/Artifact` still see marks as ordinary text; readers that honour it skip them when
  reading aloud or reflowing — the intended PDF 1.7/2.0 behaviour.
* Page marks do not re-tag the structure tree: they are artifacts by design.
