# ZOOD PDF — owner's specification (verbatim)

You are building ZOOD PDF (Arabic: زود PDF), an open, account-free, Arabic-first, Acrobat-class PDF editor: one Rust engine, one React interface for web + desktop + browser extension + installable PWA, and a separate native SwiftUI app for iPhone/iPad. Work autonomously to completion. Do not ask me questions: every decision you need is below; where something is impossible, write why in `docs/STATUS.md` and move on. Do not build façades: a control that is shown must work; "coming soon" is forbidden.

## 1. Non-negotiables

* Every PDF/photo is hostile input: no `eval`, strict CSP, bounded loops/allocations, no panics on bad input, fuzz targets on parsers.
* No telemetry, no accounts, no analytics/crash SDKs. Nothing leaves the device unless the user clicks a cloud or AI action; AI is bring-your-own-key (Anthropic) or local (Ollama :11434, LM Studio :1234); the exact text is shown before Send.
* Always keep the original bytes untouched until the user saves; edits are incremental updates. Redaction, password changes and files > 150 MB are the only whole rewrites.
* Licences: MIT/Apache-2.0/BSD/ISC/OFL/CC0 only; never GPL/AGPL/LGPL (so no veraPDF, no paperless-ngx, no LibreOffice). Keep `THIRD-PARTY-NOTICES.md` current and ship licences in builds. No client secrets in binaries. No Adobe/Apple icons, names or artwork; original icon only.
* Arabic first: every string in `en.json` and `ar.json` (natural MSA), RTL mirrored layouts, Arabic numerals per locale, Arabic text written into PDFs is shaped and reads back correctly (ActualText per word). The app name is ZOOD PDF / زود PDF everywhere (Mac bundle, window, Dock, tab, extension, iOS).
* TDD; every feature proven by a Playwright test that clicks through the real interface, saves, reopens and inspects bytes; honest `docs/STATUS.md` + `docs/feature-matrix.md`; ADRs in `docs/decisions/`.

## 2. Foundation — use exactly these, do not research alternatives

* Viewer + 5 tools (Comment, Fill & sign, Prepare form fields, Redact marks/apply, Protect): `@embedpdf/*` 2.15.1 (MIT, PDFium→WASM). Bundle its Arabic fallback font and stamps as assets; patch its hard-coded English strings at build time; disable its own Open/Close/Download; theme it via its CSS variables; add Arabic (`ar`) locale.
* Rust engine (`packages/core`, workspace): `warraq-pdf` (object layer on `lopdf` 0.45 + own encryption handler RC4/AES-128/AES-256 R2–R6 because lopdf drops encrypted objects; incremental writer; `rebase` = append only objects PDFium changed, compared by object number, so EmbedPDF saves keep original bytes/signatures), `warraq-text` (`harfrust` shaping, `unicode-bidi` with the W5 fix, extraction in logical order, Arabic-aware search normalisation: tashkeel/tatweel dropped, alef/taa-marbuta/yaa/digit forms unified, NFKC only when it changes the char; paragraph detection by columns + sentence ends + indents; Nastaliq ordering rule for kerned ligatures), `warraq-render` (`hayro` glyph/raster backend; `pdfium-render` optional native backend), `warraq-sign` (RustCrypto: `cms`, `x509-cert`, `rsa`, `p256/p384`, `sha2`, `pkcs12` legacy 3DES/RC2, `x509-tsp`, `x509-ocsp`; `webpki-roots` only for TSAs, never as document trust), `warraq-core` (JSON+blobs RPC `Document::call` / `call_static`; `wasm.rs` via wasm-pack; `ffi.rs` C ABI + `staticlib` for iOS; `cdylib`+`rlib`).
* Interface (`packages/ui`): React 19 + Vite 8 + vitest; services layer (`AppContext`) hands documents between EmbedPDF and the core as bytes (`warraqOwnsDocument`, synchronous `switching` in the reducer); tesseract.js 7 for OCR with bundled `ara/eng/fas/urd` best-int models; own deskew (projection profile), Sauvola binarisation, shadow flattening, despeckle.
* Hosts: `apps/web` (PWA: manifest, offline service worker caching the shell only), `apps/desktop` Tauri 2 (must declare `custom-protocol` feature; native file dialogs and `plugin:fs|write_file` because WKWebView ignores `<input type=file>` and `<a download>`; OS drag-drop re-emitted as a host event with pointer position (macOS/Linux already logical, scale only on Windows); macOS print via `objc2-pdf-kit`; Windows/Linux print as 300-dpi page images; native macOS menu bar built from the web menu model, title bar merged into toolbar; Windows installer NSIS only (MSI cannot write Arabic name)), `apps/extension` MV3 (locales, minimal permissions), `apps/ios` SwiftUI (XcodeGen `project.yml`; engine as XCFramework via `scripts/ios/build-core.sh`; PDFKit, VisionKit, Vision OCR, PencilKit, WidgetKit, App Intents, Core Spotlight; iOS 18+, Swift 6 strict; simulator-tested; a device needs my Apple team).
* Tooling: pnpm monorepo, eslint+stylelint (logical CSS properties), `cargo fmt/clippy -D warnings`, Playwright on Chrome (production build, own port), `scripts/verify.sh` (builds the WASM first, then lint/unit/typecheck/web+ext builds/core tests/Arabic acid gate/desktop tests/e2e — one command, GREEN or RED), `scripts/install-macos.sh`, GitHub Actions for CI + Windows installer.

4. Deliverables: `/Applications/ZOOD PDF.app` via `install-macos.sh`; web `dist` zip with a `Start on Windows.cmd` + dependency-free server; extension zip; Windows NSIS installer via GitHub Actions; iOS via `scripts/ios/build.sh` on iPhone 17 + iPad Pro simulators with screenshots in `docs/design/ios/`.

## 6. Known traps (avoid them from the start)

Tauri dev-build without `custom-protocol`; `<meta>` CSP intersecting Tauri's (strip it in desktop builds); EmbedPDF revokes its blob URL right after click (capture synchronously); PDFium writes files whole (use rebase); `/Direction R2L` makes PDFium read lines backwards (don't write it); bold text drawn fill+stroke reads twice; Amiri kerned lam-alef/kaf-taa ordering; hayro gives no marked-content properties (pre-scan with lopdf); font identity keyed by pointer without holding the Arc; shared cargo target dirs hand back another tree's WASM (build in a private dir, always rebuild the WASM before e2e); Chrome keeps writing its profile after kill (wait before rm); corepack's expired keys on Node 20 (require Node 22); WiX can't write Arabic names; wry drag positions are logical on macOS/Linux; Xcode's linker can't read Rust thin-LTO bitcode (LTO off for the iOS profile); `xcodebuild test` may hang after the last bundle (time-box it); Vision OCR Arabic support must be checked at runtime.
