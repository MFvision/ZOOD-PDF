# Feature matrix (Acrobat Pro parity map)

Status legend: ✅ done · 🟡 partial · ⬜ planned · ❌ out of scope. Targets: D = desktop, X = extension, W = web, M = mobile (Phase 9).

| Area | Feature | Tier | D | X | W | Status / notes |
|---|---|---|---|---|---|---|
| View | Open, zoom, fit modes, continuous scroll, thumbnails | MVP | ✅ | ✅ | ✅ | EmbedPDF (PDFium in WebAssembly) in all three hosts (ADR-0007); Warraq's own engine in Edit text. Menus, shortcuts, Go to page and the status bar act on the view on screen. On desktop the file comes in through the native open panel, an OS drop or a path on the command line, and goes out through the native save panel — a webview ignores the browser equivalents. The extension is proven by a test that loads it into Chrome |
| View | Bookmarks, attachments, layers panes | MVP | ✅ | ✅ | ✅ | Warraq's navigation pane, in both views (beside EmbedPDF's page view and beside the thumbnails in Edit text), opened from View → Bookmarks / Attachments / Layers, read by Warraq's core. Bookmarks: the outline with its levels, open/closed as the file says, a click goes to the page. Attachments: the document's and those on pages, with name, size, description; saved as an opaque file through the save panel (never opened or run), added (any file, with a description) and removed, as updates of the file. Layers: the order tree with groups, locked layers, print/export states shown; showing or hiding one changes only a copy the view draws until *Save layer visibility with the file* (e2e: the saved file is byte-identical until then). Layers are switched in the reading view; in Edit text the list is shown but not switched. EmbedPDF's own sidebar still has its outline and comments |
| View | Text selection and copy in logical order | MVP | ✅ | ✅ | ✅ | Copy (Cmd+C, or the selection menu) in EmbedPDF's view takes Warraq's reading of the glyphs PDFium highlighted, in logical order, wherever the selection has Arabic script; Latin-only selections keep PDFium's text (core `view.text`, `embed/embedText.ts`). e2e: a whole page of a Chrome-made Arabic form and of a Persian/Urdu/three-digit-script page copy exactly as the corpus truth reads (PDFium alone copies the form backwards), and one line copies as that line. The selection itself is PDFium's: on some Chrome-made files what a drag highlights jumps about the line. Edit text selects and copies from Warraq's own overlay. Run by the web e2e; the desktop and extension use the same code and core call |
| View | Arabic-aware search | MVP | ✅ | ✅ | ✅ | Cmd+F in the page view opens EmbedPDF's search panel, answered by Warraq's engine (core `view.search`): tashkeel-insensitive, alef/taa marbuta/yaa and Arabic-Indic/Persian/Western digits unified, "Case sensitive" and "Whole word" honoured; hits highlighted on EmbedPDF's pages, listed with whole-word context, next/previous (now named buttons) and a click go to them. What PDFium alone finds where Warraq's reader has nothing (running heads) is kept beside it. e2e: seven "وراق" on three pages where PDFium finds none, the same with the shadda, next/previous across pages; مكتبه finds المكتبة; 0123 finds ٠١٢٣, ۰۱۲۳ and 0123. Also the find bar in Edit text and Redact's find and redact. Run by the web e2e; the desktop and extension use the same code and core call |
| View | Print | MVP | 🟡 | 🟡 | ✅ | **Web**: the file itself through the browser's PDF viewer (EmbedPDF's print dialog: all, current or chosen pages, with or without comments) — the policy had blocked its frame until now (e2e: the frame opens in Chrome's PDF viewer, no policy error). **macOS desktop**: PDFKit prints the file, vectors kept (tested by printing into a PDF). **Windows/Linux desktop**: by pages — each page drawn by Warraq's core at 300 dpi, one to a sheet of the page's size, printed through the webview's own dialog; refuses a file that forbids printing. Proven in Chrome (e2e prints it to a PDF: three pages of the right size, one 300 dpi picture each, nothing else of the app) but **not run on Windows or Linux**, which are not here; rasters, not vectors. **Extension**: EmbedPDF's print, as the web, not yet run by a test |
| Mobile | Phones and tablets: installable, offline, touch | v1 | ⬜ | — | ✅ | The web app installs (manifest: ورّاق, right to left, icons with maskable ones) and works offline after one visit: a service worker keeps the app's own files — scripts, both WebAssembly engines, fonts — never a document; OCR's models on first use. Phone layout with 44-point touch targets. e2e: manifest and icons; offline, a PDF opens, draws and is searched; at 390 points, in Arabic, by touch: open, choose a tool from the gallery, use it in the sheet, menus — no target under 44 points, nothing scrolls sideways. Tested in desktop Chrome with touch emulated, not on a phone. **Native iOS/Android apps (D column)**: `tauri ios/android init` blocked on this Mac (no Homebrew/xcodegen, no Android SDK); owner steps in STATUS |
| Comment | Highlight, underline, strikeout, sticky notes, drawing, shapes, stamps, text boxes, callouts, measurement | MVP | ✅ | ✅ | ✅ | EmbedPDF's annotation plugin, saved as standard PDF annotations (e2e: a drawing survives save and reopen). Measurement not yet. Arabic typed into a text box is drawn into the saved file by Warraq's shaping, the box grown to fit (e2e; checked in PDFium) |
| Organize | Insert, delete, rotate, reorder, extract, split, merge, crop | MVP | ✅ | ✅ | ✅ | Warraq's core (ADR-0008): rotate, reorder (drag or buttons), delete, insert a blank page or every page of another PDF (with its password, if it has one), extract as a new file and split into files (every so many pages or at the selected pages, one zip) and crop (margins as the page is shown, or the white trimmed away) work, with undo, as incremental updates (e2e: moved, turned, deleted pages keep their text through save and reopen). Combine files merges several (e2e: order kept, page by page by their text; a protected input opened with its password), keeping every form field |
| Compress | Image downsampling, object streams, font subsetting, presets | MVP | ✅ | ✅ | ✅ | Warraq's core, pure Rust in every host: unused objects dropped, duplicate streams shared, best Flate, object and xref streams; optional downsampling of oversized 8-bit grey/RGB images to 150 or 96 dpi JPEG (e2e: a 300 dpi scan more than halved; every page's text kept, checked on a 95-page Word export). Refuses protected and signed files. Font re-subsetting not yet |
| Fill & Sign | AcroForm fill, draw/type/image signature, initials, dates | MVP | ✅ | ✅ | ✅ | EmbedPDF's form and signature plugins (e2e: a typed value survives save and reopen). Arabic values are drawn into the saved file by Warraq's shaping, where PDFium wrote an empty appearance (e2e; checked in PDFium). On desktop the signature image is chosen in the native open panel (`core/desktopFiles.ts`) |
| Protect | Open password, AES-256 | MVP | 🟡 | 🟡 | 🟡 | EmbedPDF sets an open password and permissions (e2e: the saved file is encrypted and reopens only with its password, through Warraq's prompt, in both engines). Warraq's core reads R2–R6 (RC4 40/128, AES-128, AES-256) and keeps the protection on what it appends — a text edit or a page change saves encrypted with the file's own key (checked by PDFium; e2e: edit, save, the password is still asked for) |
| Edit PDF | Add a line of text where you click | MVP | ✅ | ✅ | ✅ | shaped, subset and embedded like any replacement, in a chosen face (Amiri, Cairo, Inter) and size; RTL grows leftwards from the point. Not on the undo stack yet |
| Edit PDF | Text edit with reflow (Arabic-correct) | MVP | ✅ | ✅ | ✅ | click a paragraph, edit in place, undo/redo, save. GATE 2 passed on a real Word export and a scan (`docs/gate-2.md`); Acrobat verification still outstanding |
| Edit PDF | Images replace/resize/crop, links, headers/footers, watermarks, Bates, page numbers | MVP/v1 | ✅ | ✅ | ✅ | Warraq's core. **Page marks** (its own tool): text or picture watermarks (size, colour, opacity, rotation, centre/corners/tiled, in front or behind), headers and footers in three slots with page, page-count, file-name and date tokens (Gregorian or Hijri Umm al-Qura, Western or Arabic-Indic digits; "start" is the right side in Arabic), page numbers (`1`, `1 / 9`, `Page 1 of 9`, `صفحة ١ من ٩`, roman; start number, skip the first page) and Bates numbers (prefix, start, padding, suffix), on any page range, previewed on the page by the core. Each mark is a form XObject tagged as a pagination artifact with Warraq's `/PieceInfo`, round the page's own streams, so it is listed, replaced and taken off leaving the page as it was (e2e: Arabic header, `صفحة ١ من ٣` and a watermark read back from the saved file by Warraq's reader and kept out of its text; red checked in PDFium's rendering; all taken off again). The reader leaves artifacts out of a page's text. **Edit → Pictures**: pick, move, resize (Shift keeps proportions), turn 90°, crop, replace, delete, or place a PNG/JPEG by dragging (inline images and pictures in forms too), each rewriting only the one operation's stream (e2e: positions and crop read back from the saved file). **Edit → Links**: draw, point at an address or a page, move, resize, remove (e2e). An address never opens without asking, in either view; only http, https and mailto open, in the system browser. A picture drawn by a form used in several places is shown but not editable |
| Scan & OCR | Arabic + English OCR, deskew, cleanup, searchable image PDF | v1 | 🟡 | ✅ | ✅ | tesseract.js 7 in every host (the desktop webview too), models bundled (ara, eng, fas, urd "best int"); an invisible, shaped text layer written by Warraq's core as an incremental update (e2e: 94 % of the Arabic words of a 300 dpi scan, read back after save and reopen). crooked pages are straightened before they are read (e2e: 93 % of a page 8° off true, against 56 % unstraightened); no cleanup yet; desktop recognition not yet watched |
| Export / Create | PDF → Word/Excel/PowerPoint/images/HTML/text; Office/images/HTML → PDF; combine | v1 | 🟡 | 🟡 | 🟡 | PDF → Word (flowing right-to-left paragraphs, text only; valid against the ISO/IEC 29500 schemas, not yet opened in Word), text, Markdown, HTML and PNG page images, from Warraq's own logical-order text (e2e: every format; redactions never leak). Excel, PowerPoint and anything → PDF not yet |
| Prepare Form | Create fields, auto-detect, calculations, safe JS subset | v1 | ✅ | ✅ | ✅ | Fields by hand: EmbedPDF's text fields, checkboxes, radio buttons, drop-downs and list boxes (e2e). **Auto-detect** (Warraq's core): underscore and dot runs, `__/__/____` dates, empty table cells beside their label or under a column heading, drawn boxes, lines to write or sign on, drawn and typed (☐) check boxes — named from their Arabic or English label, typed text / check box / date / Hijri date / signature, right-to-left (`/Q 2`) for Arabic; proposals drawn on the page to move, resize, rename, retype or remove, then created as AcroForm fields (e2e: a flat Arabic invoice). Measured on 92 labelled fields in 10 Chrome-printed forms: precision and recall 1.00, type and name 1.00 (held-out set first measured at recall 0.96, type 0.74, name 0.78, then fixed); 36 of 41 non-form corpus files get no proposal. **Formats, ranges, calculations**: number (decimals, separators, negatives, SAR/ر.س, Arabic-Indic digits), percent, date, Umm al-Qura Hijri date; `AFRange_Validate`; sum/product/average/min/max or a typed arithmetic expression — written as `/AA` `/K` `/F` `/V` `/C` with Acrobat's built-in functions and `/CO` in dependency order, run inside Warraq by its own bounded interpreter of that subset (no eval); filling a field in EmbedPDF recalculates, a refused value is put back (e2e). Scripts outside the subset are listed, never run. **XFA**: static XFA fills through its AcroForm and can have its XFA layer removed (e2e); dynamic XFA is said to be one and not rendered |
| Redact | Text, area, search-and-redact, metadata scrub, true removal | v1 | ✅ | ✅ | ✅ | EmbedPDF marks text or an area and applies it as true removal (e2e: the text is gone from the saved file, the rest is intact). Find and redact: Warraq's Arabic-aware search (diacritics, alef/taa/yaa/digit forms) plus ready-made patterns — emails, Saudi and international phones in Latin or Arabic-Indic digits, national ID/Iqama, IBAN (mod 97), card numbers (Luhn), Arabic/English/Hijri-month dates — or a person's own linear-time regex; each match listed with page and context, chosen ones become EmbedPDF's own pending marks over their glyph boxes (e2e: an Arabic word, an English word and an email marked, applied, saved; gone for Warraq's reader and from every inflated content stream, literal or hex, and as ActualText; the rest intact). Remove hidden information: a report of metadata/XMP, scripts and actions, attachments, comments, form data (fields flattened into the page), hidden layers, bookmarks, thumbnails, PieceInfo, links, hidden text (invisible, white, off-page), earlier revisions and unreferenced objects; removal writes the file whole (Rust tests grep the bytes and inflated streams for each item; e2e: every marker gone from the saved file, one revision). Limits: text hidden under an image or by a clip path is not detected, nor hidden text inside form XObjects; protected files are refused (the rewrite would lose the password) |
| Compare | Text + visual diff | v1 | ✅ | ✅ | ✅ | the text of two versions — the file's own earlier revisions or another PDF — word by word, Arabic-aware, and how each page looks, drawn and compared with the changes outlined; a report with both (e2e: an earlier revision, another PDF, a diacritics-only change, a protected copy, a drawing only the pictures show) |
| Signatures | PAdES sign (PKCS#12, smart card), verify chain, timestamps, LTV | v1 | 🟡 | 🟡 | 🟡 | Warraq's core (`warraq-sign`, RustCrypto, no OpenSSL), the Digital signature tool: PAdES B-B from a .p12/.pfx (legacy 3DES/RC2-40 and PBES2/AES), RSA PKCS#1 v1.5 and PSS, ECDSA P-256/P-384; visible (dragged on the page, Arabic shaped, optional picture) or invisible, or into an empty field; approval or certification (DocMDP 1–3), field locking (FieldMDP); on protected files too. Verify on open: integrity, chain to Mozilla's roots or the person's own, validity at signing time, timestamp, revocation data in the file, and changes after signing judged against DocMDP and locks (e2e: sign, PDFium lists it, save keeps the signed bytes, reopen, trust, valid; a changed byte, invalid; `openssl cms -verify` agrees in the Rust tests). Desktop only: B-T signature timestamps and B-LTA document timestamps from a chosen authority, and B-LT validation data (OCSP/CRL/certificates into `/DSS`) — run against DigiCert's and Sectigo's real services; the browser cannot read those servers' answers (no CORS), and says so. Smart cards (PKCS#11, desktop) built but untested with hardware; ❌ in the extension and web |
