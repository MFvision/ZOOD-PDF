# Feature matrix (Acrobat Pro parity map)

Status legend: ✅ done · 🟡 partial · ⬜ planned · ❌ out of scope. Targets: D = desktop, X = extension, W = web, M = mobile (Phase 9).

| Area | Feature | Tier | D | X | W | Status / notes |
|---|---|---|---|---|---|---|
| View | Open, zoom, fit modes, continuous scroll, thumbnails | MVP | ✅ | ✅ | ✅ | EmbedPDF (PDFium in WebAssembly) in all three hosts (ADR-0007); Warraq's own engine in Edit text. Menus, shortcuts, Go to page and the status bar act on the view on screen. On desktop the file comes in through the native open panel, an OS drop or a path on the command line, and goes out through the native save panel — a webview ignores the browser equivalents. The extension is proven by a test that loads it into Chrome |
| View | Bookmarks, attachments, layers panes | MVP | ✅ | ✅ | ✅ | Warraq's navigation pane, in both views (beside EmbedPDF's page view and beside the thumbnails in Edit text), opened from View → Bookmarks / Attachments / Layers, read by Warraq's core. Bookmarks: the outline with its levels, open/closed as the file says, a click or Enter goes to the page; headings with no page are headings, and only entries that leave the file say so; the tree and the pane tabs have the arrow-key behaviour of their roles, mirrored in Arabic (e2e). Attachments: the document's and those on pages, with name, size, description; saved as an opaque file through the save panel (never opened or run), added (any file, with a description) and removed, as updates of the file — in Edit text without losing its undo history (e2e). Layers: the order tree with groups, locked layers, print/export states shown; showing or hiding one changes only a copy the view draws until *Save layer visibility with the file* (e2e: the saved file is byte-identical until then). Layers are switched in the reading view; in Edit text the list is shown but not switched. EmbedPDF's own sidebar still has its outline and comments |
| View | Text selection and copy in logical order | MVP | ✅ | ✅ | ✅ | Copy (Cmd+C, or the selection menu) in EmbedPDF's view takes Warraq's reading of the glyphs PDFium highlighted, in logical order, wherever the selection has Arabic script; Latin-only selections keep PDFium's text (core `view.text`, `embed/embedText.ts`). e2e: a whole page of a Chrome-made Arabic form and of a Persian/Urdu/three-digit-script page copy exactly as the corpus truth reads (PDFium alone copies the form backwards), and one line copies as that line. The selection itself is PDFium's: on some Chrome-made files what a drag highlights jumps about the line. Edit text selects and copies from Warraq's own overlay. Run by the web e2e; the desktop and extension use the same code and core call |
| View | Arabic-aware search | MVP | ✅ | ✅ | ✅ | Cmd+F in the page view opens EmbedPDF's search panel, answered by Warraq's engine (core `view.search`): tashkeel-insensitive, alef/taa marbuta/yaa and Arabic-Indic/Persian/Western digits unified, "Case sensitive" and "Whole word" honoured; hits highlighted on EmbedPDF's pages, listed with whole-word context, next/previous (now named buttons) and a click go to them. What PDFium alone finds where Warraq's reader has nothing (running heads) is kept beside it. e2e: seven "وراق" on three pages where PDFium finds none, the same with the shadda, next/previous across pages; مكتبه finds المكتبة; 0123 finds ٠١٢٣, ۰۱۲۳ and 0123. Also the find bar in Edit text and Redact's find and redact. Run by the web e2e; the desktop and extension use the same code and core call |
| View | Print | MVP | 🟡 | 🟡 | ✅ | **Web**: the file itself through the browser's PDF viewer (EmbedPDF's print dialog: all, current or chosen pages, with or without comments) — the policy had blocked its frame until now (e2e: the frame opens in Chrome's PDF viewer, no policy error). **macOS desktop**: PDFKit prints the file, vectors kept (tested by printing into a PDF). **Windows/Linux desktop**: by pages — each page drawn by Warraq's core at 300 dpi, one to a sheet of the page's size, printed through the webview's own dialog; refuses a file that forbids printing. Proven in Chrome (e2e prints it to a PDF: three pages of the right size, one 300 dpi picture each, nothing else of the app) but **not run on Windows or Linux**, which are not here; rasters, not vectors. **Extension**: EmbedPDF's print, as the web, not yet run by a test |
| Mobile | Phones and tablets: installable, offline, touch | v1 | ⬜ | — | ✅ | The web app installs (manifest: محرر PDF, right to left, icons with maskable ones) and works offline after one visit: a service worker keeps the app's own files — scripts, both WebAssembly engines, fonts — never a document; OCR's models on first use. Phone layout with 44-point touch targets. e2e: manifest and icons; offline, a PDF opens, draws and is searched; at 390 points, in Arabic, by touch: open, choose a tool from the gallery, use it in the sheet, menus — no target under 44 points, nothing scrolls sideways. Tested in desktop Chrome with touch emulated, not on a phone. **Native iOS/Android apps (D column)**: `tauri ios/android init` blocked on this Mac (no Homebrew/xcodegen, no Android SDK); owner steps in STATUS |
| Comment | Highlight, underline, strikeout, sticky notes, drawing, shapes, stamps, text boxes, callouts, measurement | MVP | ✅ | ✅ | ✅ | EmbedPDF's annotation plugin, saved as standard PDF annotations (e2e: a drawing survives save and reopen). Measurement not yet. Arabic typed into a text box is drawn into the saved file by Warraq's shaping, the box grown to fit (e2e; checked in PDFium) |
| Organize | Insert, delete, rotate, reorder, extract, split, merge, crop | MVP | ✅ | ✅ | ✅ | Warraq's core (ADR-0008): rotate, reorder (drag or buttons), delete, insert a blank page or every page of another PDF (with its password, if it has one), extract as a new file and split into files (every so many pages or at the selected pages, one zip) and crop (margins as the page is shown, or the white trimmed away) work, with undo, as incremental updates (e2e: moved, turned, deleted pages keep their text through save and reopen). Combine files merges several (e2e: order kept, page by page by their text; a protected input opened with its password), keeping every form field |
| Compress | Image downsampling, object streams, font subsetting, presets | MVP | ✅ | ✅ | ✅ | Warraq's core, pure Rust in every host: unused objects dropped, duplicate streams shared, best Flate, object and xref streams; optional downsampling of oversized 8-bit grey/RGB images to 150 or 96 dpi JPEG (e2e: a 300 dpi scan more than halved; every page's text kept, checked on a 95-page Word export). Refuses protected and signed files. Font re-subsetting not yet |
| Fill & Sign | AcroForm fill, draw/type/image signature, initials, dates | MVP | ✅ | ✅ | ✅ | EmbedPDF's form and signature plugins (e2e: a typed value survives save and reopen). Arabic values are drawn into the saved file by Warraq's shaping, where PDFium wrote an empty appearance (e2e; checked in PDFium). On desktop the signature image is chosen in the native open panel (`core/desktopFiles.ts`) |
| Protect | Open password, AES-256 | MVP | 🟡 | 🟡 | 🟡 | EmbedPDF sets an open password and permissions (e2e: the saved file is encrypted and reopens only with its password, through Warraq's prompt, in both engines). Warraq's core reads R2–R6 (RC4 40/128, AES-128, AES-256) and keeps the protection on what it appends — a text edit or a page change saves encrypted with the file's own key (checked by PDFium; e2e: edit, save, the password is still asked for) |
| Edit PDF | Add a line of text where you click | MVP | ✅ | ✅ | ✅ | shaped, subset and embedded like any replacement, in a chosen face (Amiri, Cairo, Inter) and size; RTL grows leftwards from the point. On the undo stack with every Edit change: the file before it is kept, and Undo puts it back |
| Edit PDF | Text edit with reflow (Arabic-correct) | MVP | ✅ | ✅ | ✅ | click a paragraph, edit in place, undo/redo, save. GATE 2 passed on a real Word export and a scan (`docs/gate-2.md`); Acrobat verification still outstanding |
| Edit PDF | Images replace/resize/crop, links, headers/footers, watermarks, Bates, page numbers | MVP/v1 | ✅ | ✅ | ✅ | Warraq's core. **Page marks** (its own tool): text or picture watermarks (size, colour, opacity, rotation, centre/corners/tiled, in front or behind), headers and footers in three slots with page, page-count, file-name and date tokens (Gregorian or Hijri Umm al-Qura, Western or Arabic-Indic digits; "start" is the right side in Arabic), page numbers (`1`, `1 / 9`, `Page 1 of 9`, `صفحة ١ من ٩`, roman — labelled in the digits chosen; start number, skip the first page) and Bates numbers (prefix, start, padding, suffix), on any page range, previewed on the page by the core. Each mark is a form XObject tagged as a pagination artifact with Warraq's `/PieceInfo`, round the page's own streams, so it is listed, replaced and taken off leaving the page as it was (e2e: Arabic header, `صفحة ١ من ٣` and a watermark read back from the saved file by Warraq's reader and kept out of its text; red checked in PDFium's rendering; all taken off again). Warraq's reader leaves its own marks out of a page's text (Edit, Export, Compare); other programs' artifacts stay in it, and search and Find and redact read everything (Rust test: a Word-style footer's e-mail is found). A small tiled watermark covers the whole page (Rust test). **Edit → Pictures**: pick, move, resize (Shift keeps proportions), turn 90°, crop, replace, delete, or place a PNG/JPEG by dragging (inline images and pictures in forms too), each rewriting only the one operation's stream (e2e: positions and crop read back from the saved file); arrow keys nudge the picked picture (e2e: two presses, two points); every picture, link and added-text change undone and redone in turn with text edits (e2e: Undo takes back the picture, not the text before it). Deleting or replacing a picture takes it out of the page's resources; a picture a form or content stream shares with another page is not edited; a picture in a form stays inside the form's box; a phone photo is placed, replaced and used as a watermark upright (EXIF), its JPEG kept byte for byte — Rust tests. The content lexer and picture walker are bounded against hostile streams (Rust tests, a stable harness, `fuzz/lex_content`). **Edit → Links** (e2e for each): draw, or add one from the panel; point at an address or a page; move by dragging or with the arrow keys; resize with a handle or Alt+arrow; point elsewhere; remove. A link written straight into `/Annots` is changed and removed in place (Rust test). An address never opens without asking, in either view; only http, https and mailto open, in the system browser; one with bidi controls or other invisible characters is refused and shown escaped (e2e, Rust and vitest), and the question shows an address in letters with the site it really opens. On desktop the confirmed address goes through `open_url`, not yet clicked in the installed window. A picture whose drawing is shared — a form used twice or drawn on another page, a content stream two pages list — is shown but not editable |
| Scan & OCR | Arabic + English OCR, deskew, cleanup, searchable image PDF | v1 | 🟡 | ✅ | ✅ | tesseract.js 7 in every host (the desktop webview too), models bundled (ara, eng, fas, urd "best int"); an invisible, shaped text layer written by Warraq's core as an incremental update (e2e: 94 % of the Arabic words of a 300 dpi scan, read back after save and reopen). crooked pages are straightened before they are read (e2e: 93 % of a page 8° off true, against 56 % unstraightened); no cleanup yet; desktop recognition not yet watched |
| Export / Create | PDF → Word/Excel/PowerPoint/images/HTML/text; Office/images/HTML → PDF; combine | v1 | 🟡 | 🟡 | ✅ | PDF → Word (flowing right-to-left paragraphs, text only), **Excel** (tables found from ruling lines and column alignment, merged cells, numbers as numbers incl. Arabic-Indic digits, right-to-left sheets; a sheet per page or per table), **PowerPoint** (the page without its text as the background, editable positioned right-to-left text boxes; or text only), text, Markdown, HTML and PNG page images, all from Warraq's own logical-order text. **Create PDF**: Word, Excel, PowerPoint, web pages (safe subset), Markdown, text, CSV and pictures (PNG, JPEG, GIF, BMP, WebP, multi-page TIFF incl. fax; HEIC/AVIF where the browser decodes them) → PDF with Warraq's own layout engine in the core (shaped Arabic, runs, lists, tables, pictures, headers/footers with page numbers, slides' boxes), page size/orientation/margins, several files → one in order, optional OCR after; from the home screen, the tool or a drop. The desktop app and the extension run the same code (the desktop's native open panel and drop for Create included) but have not been exercised with it |
| Prepare Form | Create fields, auto-detect, calculations, safe JS subset | v1 | ✅ | ✅ | ✅ | Fields by hand: EmbedPDF's text fields, checkboxes, radio buttons, drop-downs and list boxes (e2e). **Auto-detect** (Warraq's core): underscore and dot runs, `__/__/____` dates, empty table cells beside their label or under a column heading, drawn boxes, lines to write or sign on, drawn and typed (☐) check boxes — named from their Arabic or English label, typed text / check box / date / Hijri date / signature, right-to-left (`/Q 2`) for Arabic; proposals drawn on the page to move, resize, rename, retype or remove, then created as AcroForm fields (e2e: a flat Arabic invoice). Measured on 92 labelled fields in 10 Chrome-printed forms: precision and recall 1.00, type and name 1.00 (held-out set first measured at recall 0.96, type 0.74, name 0.78, then fixed); 36 of 41 non-form corpus files get no proposal. **Formats, ranges, calculations**: number (decimals, separators, negatives, SAR/ر.س, Arabic-Indic digits), percent, date, Umm al-Qura Hijri date; `AFRange_Validate`; sum/product/average/min/max or a typed arithmetic expression — written as `/AA` `/K` `/F` `/V` `/C` with Acrobat's built-in functions and `/CO` in dependency order, run inside Warraq by its own bounded interpreter of that subset (no eval); filling a field in EmbedPDF recalculates, a refused value is put back (e2e). Scripts outside the subset are listed, never run. **XFA**: static XFA fills through its AcroForm and can have its XFA layer removed (e2e); dynamic XFA is said to be one and not rendered |
| Redact | Text, area, search-and-redact, metadata scrub, true removal | v1 | ✅ | ✅ | ✅ | EmbedPDF marks text or an area and applies it as true removal (e2e: the text is gone from the saved file, the rest is intact). Find and redact: Warraq's Arabic-aware search (diacritics, alef/taa/yaa/digit forms), over everything on the page — running heads, footers and page marks included — plus ready-made patterns — emails, Saudi and international phones in Latin or Arabic-Indic digits, national ID/Iqama, IBAN (mod 97), card numbers (Luhn), Arabic/English/Hijri-month dates — or a person's own linear-time regex; overlapping hits merged; a match in a page mark محرر PDF drew said to be one; each match listed with page and context, chosen ones become EmbedPDF's own pending marks over their glyph boxes — on pages turned by /Rotate and on slanting or upright lines, each char where it was drawn; a match whose glyphs the reader cannot place is listed to mark by hand, never guessed (e2e: an Arabic word, an English word and an email marked, applied, saved; gone for Warraq's reader and from every inflated content stream, literal or hex, and as ActualText; the rest intact; the same on /Rotate 90/180/270 pages, an 8° page, an upright margin line and a footer another program marked as an artifact, with every neighbouring word kept; a Page marks header found, labelled and redacted). A file whose permissions forbid changing its content takes no marks and the panel says so (e2e); results belong to the file they were found in (e2e); with layers shown by choice, a redaction survives Edit text and Save (e2e: nowhere in the saved bytes). Remove hidden information: a report, in the interface's language, of metadata/XMP, scripts and actions (chained through /Next and held by reference too), attachments, comments, form data (fields flattened into the page), hidden layers (as PDFium decides them: view state, OCMD policies and expressions; a layer shown content still depends on stays, off), bookmarks, thumbnails, PieceInfo, links, hidden text (invisible, white on white, off-page), earlier revisions and unreferenced objects; removal writes the file whole, with what still pointed at a removed annotation or field — a tagged file's structure tree — taken out (Rust tests grep the bytes and inflated streams for each item, on a tagged fixture; e2e: every marker gone from the saved file, one revision). Limits: text hidden under an image or by a clip path is not detected, nor hidden text inside form XObjects; white text beside a dark shape but inside its box is taken as seen; protected files are refused (the rewrite would lose the password) |

| Signatures | PAdES sign (PKCS#12, smart card), verify chain, timestamps, LTV | v1 | 🟡 | 🟡 | 🟡 | Warraq's core (`warraq-sign`, RustCrypto, no OpenSSL), the Digital signature tool: PAdES B-B from a .p12/.pfx (legacy 3DES/RC2-40 and PBES2/AES), RSA PKCS#1 v1.5 and PSS, ECDSA P-256/P-384; visible (dragged on the page, Arabic shaped, optional picture) or invisible, or into an empty field; approval or certification (DocMDP 1–3), field locking (FieldMDP, Include/Exclude kept); on protected files too. Verify on open: integrity, the signature dictionary tied to the revision it signed, the chain, validity at a trusted time or now, timestamp, revocation data in the file, and changes after signing judged against DocMDP and locks — trailer, shadow objects, fields added vs filled, signature appearances. Trust: a signer is valid only under a certificate the person trusts, with a document-signing purpose; Mozilla's web-site roots show as "identity not verified", and vouch only for timestamp authorities (e2e: sign, PDFium lists it, save keeps the signed bytes, reopen, trust, valid; a changed byte, invalid, said in words; placement where drawn; an empty field signed into; `openssl cms -verify` agrees in the Rust tests; 16 hostile-file and hostile-certificate tests in `attacks.rs`). Desktop only: B-T signature timestamps and B-LTA document timestamps from a chosen authority, and B-LT validation data (OCSP/CRL/certificates into `/DSS`) — run against DigiCert's and Sectigo's real services; the browser cannot read those servers' answers (no CORS), and says so.
